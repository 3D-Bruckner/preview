# preview v0.2, step 2: plates, parts, measurements, view tools — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A version knows its plates, parts and filament slots (read once from the 3MF at upload); the customer's model page shows one plate or all, lists the parts with an eye and a hover highlight, colours them by filament, gives the measurements and the view tools.

**Architecture:** A new framework-free `backend/threemf/` reads the 3MF's small entries (Bambu's `Metadata/*.config`, the root `3D/3dmodel.model`) through a bounded, streaming unzip and an attributes-only XML tag scanner, and returns the version's **facts** (JSON, stored in a new `versions.facts` column). The same scanner is pure and goes to the browser through `@/backend/client`, where an own small 3MF mesh loader (`components/viewer/threemf.ts`) replaces three's `ThreeMFLoader`: it builds one mesh per build item × component and tags it with the facts' part key. `scene.ts` grows a plate/part API; a client `ModelReview` component holds the state shared by the viewer, the plate strip and the side panel.

**Tech Stack:** Next.js (App Router), three 0.187, fflate (`Unzip` streaming), Vitest (node environment: no DOMParser), Playwright.

**Spec:** `docs/superpowers/specs/2026-11-27-preview-v0.2-design.md` (Goals 2–5; Design: "What preview reads from a 3MF", "The customer pages", the viewer bullet; "Claude's calls": part granularity, measurements in the browser, facts computed once + `reread_facts`). Mock: `/root/3D-Bruckner/preview-designs/Open Design/vorschau-app/vorschau-app.html` (toolbar, plate strip, Maße, Teile). Print figures (`slice_info.config`), the slicer, filaments, pickers and feedback are steps 3 and 4: leave no placeholders for them.

**Reference file (real Bambu Studio 2.6 project, 5 plates):** `/root/3D-Bruckner/bambuddy-wiki/docs/assets/3d-models/SpoolBuddy.3mf`. What it shows, and the reader must handle:
- Root `3D/3dmodel.model`: objects with `<components>` only, each `<component p:path="/3D/Objects/object_6.model" objectid="5" transform="…">`; meshes live in `3D/Objects/*.model`, whose object ids are their own namespace (root ids 2, 4, 38… collide with sub-file ids: why three's loader, which keys objects globally, is replaced). `<build>` items carry `transform` and `printable`; plates are laid side by side in build space (x up to ~940 mm).
- `Metadata/model_settings.config`: `<object id="38">` (root id) with `<metadata key="name">`, `<metadata key="extruder">`, and `<part id="5" subtype="normal_part">` whose `id` is the component's `objectid` and which may carry its own `extruder` (object 38: parts on extruders 1, 2 and 3). `<plate>` with `plater_id`, `plater_name`, `thumbnail_file` (`Metadata/plate_1.png`) and `<model_instance>` (`object_id`, `instance_id`).
- `Metadata/project_settings.config` is **JSON**: `"filament_colour": ["#000000","#FFFFFF","#00AE42"]`, `"filament_type": ["PLA","PLA","PLA"]`.
- `paint_color` on triangles (painted multi-colour) exists; it is not read in this step (the part shows its extruder's colour).

## Global Constraints

- `CLAUDE.md`'s rules hold: `backend/` imports no Next/React/frontend; only `backend/db/` touches the database; changes run in `mutation(rt, fn)`; MCP and REST mirror each other (`checkOpsMirrorTools`) and every MCP result carries `guidance`; `npm run generate` after a `rest.ts` change; a new migration is appended, none edited; no literal text in JSX, every word in `components/copy/en.ts` and `de.ts`; logs hold no token, link token, file name or email.
- Every customer read starts from `customerByToken` (`backend/customerview.ts`); a plate picture is served by the same file route and gate as the preview.
- The server never inflates a 3MF entry without a bound: config entries ≤ 16 MiB inflated, a plate picture ≤ 8 MiB, the root model of a 3MF without `model_settings.config` scanned as a stream up to 1 GiB (beyond: refused, `threemf: too large inside`). The existing bomb test (300 MB of zeros) must still pass under 100 MB of extra memory. No entry under `3D/Objects/` is read on the server.
- Part key: `` `${plate}:${objectId}:${n}` `` (plate number, root object id, index of the filament group within that object, 0-based in order of first appearance); stable within a version. Only `subtype="normal_part"` (or no subtype) is a part; modifiers, negative parts and support blockers are neither listed nor drawn.
- Measurements: in the browser, from the visible meshes' bounding box in the 3MF's axes (x width, y depth, z height), in mm via the model's `unit` (micron 0.001, millimeter 1, centimeter 10, inch 25.4, foot 304.8, meter 1000). Shown whole mm, one decimal below 10 mm, German decimal comma in `de`.
- A file with one plate has no plate strip and no plate numbers. The accent is used for at most one primary action (none here: the strip and toggles use `aria-pressed` with `--fg`, as the mock).
- Motion: switching plate or view animates the camera only when `prefers-reduced-motion` is not set (otherwise it jumps).

## Review Focus

- A Bambu project where an object sits on no plate (off the beds) or a plate has no objects: the object is neither listed nor drawn; an empty plate still gets its card (0 parts) and fits to nothing gracefully (camera keeps the whole model).
- An object that appears twice on a plate (two `model_instance`s / two build items): one part row, both instances drawn, the eye and highlight act on both.
- A plain 3MF whose object has no `pid` but whose triangles carry `pid`/`p1` (newer OpenSCAD): the part's slot comes from its first triangle's material; the keychain's red and blue stay red and blue.
- `project_settings.config` that is not JSON or lacks the arrays, or an `extruder` beyond the slots: slots fall back to what is known, the part's slot becomes null (shown grey, "unbekannt"), the upload still succeeds.
- A huge Bambu project (SpoolBuddy: 8.7 MB sub-model, 5 plates, 40+ parts) on a 390 px phone: the strip scrolls sideways, the parts list does not push the page sideways, the viewer loads within the existing stall/progress behaviour.

**Interfaces:**
- Produces:
  - `type Tag = { name: string; attrs: Record<string, string>; end: boolean; selfClosing: boolean }`; `scanTags(text: string, onTag: (t: Tag) => void): void`; `class TagStream { constructor(onTag); push(chunk: string): void; end(): void }` (a tag split across chunks is handled). Entities `&amp; &lt; &gt; &quot; &apos; &#NN; &#xNN;` decoded in attribute values. Namespaced names kept as written (`p:path`).
  - `UNIT_MM: Record<string, number>` (the six units above).
  - `type FactsSlot = { slot: number; type: string | null; color: string | null }` (slot 1-based; colour `#rrggbb` lower case, alpha dropped).

  - `readEntry(bytes, name, maxBytes): Uint8Array | null` and `scanEntry(bytes, name, maxBytes, onChunk: (s: string) => void): boolean` in `zip.ts`, both on fflate's streaming `Unzip` with a running byte count that aborts past `maxBytes` (throw `FactsError`).

### Task 6: The view's plate, part and camera API

**Files:**
- Modify: `components/viewer/scene.ts`, `components/viewer/scene.test.ts`

**Interfaces:**
- Produces, on `View`:
  - `showPlate(plate: number | null): void` — null shows every plate (as laid out in the file); a number shows only that plate's meshes; both refit the camera to what is shown (animated over 300 ms unless reduced motion) and redraw the shadow.
  - `setHidden(keys: ReadonlySet<string>): void` — hides those parts' meshes (all instances); the fit does not change.
  - `highlight(key: string | null): void` — the part's meshes get an emissive of the accent at 0.35 (read from `--accent` on the mount), others stay; null clears.
  - `setCamera(dir: "iso" | "top" | "front" | "side"): void` — iso = today's opening direction `(0.8, 0.65, 1.4)`; top `(0, 1, 0.0001)`; front `(0, 0, 1)`; side `(1, 0, 0)`, at the fit distance; stops the turntable.
  - `fit(): void` — iso, refit to what is shown.
  - `size(): { x: number; y: number; z: number }` — the visible meshes' box in mm, 3MF axes (x width, y depth = scene −z extent, z height = scene y); `options.onSize(size)` is called after each `showPlate`/`setHidden`.
  - `plateAnchors(): { plate: number; x: number; y: number }[]` — screen positions (CSS px in the mount) above each shown plate's box centre, for the numbers in "Alle Platten"; `options.onFrame?.()` after each drawn frame so the caller can move them.
  - An axis gizmo bottom-left (three's `ViewHelper` addon, drawn after the scene, not clickable, `aria-hidden` by being on the canvas).
