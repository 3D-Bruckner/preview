# preview v0.2, step 2: parts, measurements, view tools — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A version knows its parts and filament slots (read once from the 3MF at upload); the customer's model page lists the parts with an eye, a focus button and a hover highlight, colours them by filament, gives the measurements and the view tools.

**Revised 2026-11-28 (Marcel):** no plates (they are the print layout and say nothing to a customer; a focused part does what showing one plate did, better), and three's `ThreeMFLoader` stays (its global object ids break only files whose sub-models reuse ids, which Bambu Studio doesn't write; checked on SpoolBuddy). The file keeps its first name so the branch's history reads in one place.

**Architecture:** A new framework-free `backend/threemf/` reads the 3MF's small entries (Bambu's `Metadata/*.config`, the root `3D/3dmodel.model`) from the zip's central directory, inflating each through fflate's streaming `Inflate` with a byte bound, and scans them with an attributes-only XML tag scanner; it returns the version's **facts** (JSON, stored in a new `versions.facts` column). In the browser, three's `ThreeMFLoader` stays; its output follows the file (one child per build item, in it one child per component, in order), so `components/viewer/parts.ts` walks it with the facts and tags each mesh with its part key, colours it and drops modifiers. `scene.ts` grows a part and camera API; a client `ModelReview` component holds the state shared by the viewer and the side panel.

**Tech Stack:** Next.js (App Router), three 0.187, fflate, Vitest (node: no DOMParser), Playwright.

**Reference file (real Bambu Studio 2.6 project, 5 plates):** `/root/3D-Bruckner/bambuddy-wiki/docs/assets/3d-models/SpoolBuddy.3mf`:
- Root `3D/3dmodel.model`: objects with `<components>` only (`<component p:path="/3D/Objects/object_6.model" objectid="5" transform="…">`); `<build>` items with `transform`, laid out across the plates (x up to ~940 mm). Object ids are unique across root and sub-models.
- `Metadata/model_settings.config`: `<object id="38">` (root id) with `<metadata key="name">`, `<metadata key="extruder">`, and `<part id="5" subtype="normal_part">` (id = the component's `objectid`), whose own `<metadata key="extruder">` may differ (object 38: 1, 3, 2); a part's own `name` metadata is inside the part.
- `Metadata/project_settings.config` is JSON: `filament_colour`, `filament_type` arrays.

## Global Constraints

- `CLAUDE.md`'s rules hold: `backend/` imports no Next/React/frontend; only `backend/db/` touches the database; changes run in `mutation(rt, fn)`; MCP and REST mirror each other and every MCP result carries `guidance`; `npm run generate` after a `rest.ts` change; a new migration is appended; no literal text in JSX, every word in `components/copy/en.ts` and `de.ts`; logs hold no token, link token, file name or email.
- Every customer read starts from `customerByToken`.
- The server never inflates a 3MF entry without a bound: config entries ≤ 16 MiB, the root model ≤ 1 GiB scanned as a stream (beyond: `threemf: too large inside`). The bomb test (300 MB of zeros) passes under 100 MB of extra memory. No entry under `3D/Objects/` is read on the server.
- Part key: `` `${objectId}:${n}` `` (root object id, index of the filament group within that object, 0-based in order of first appearance). Only `subtype="normal_part"` (or none) is a part; modifiers, negative parts and support blockers are neither listed nor drawn. An object placed twice is one part, both drawn.
- Measurements in the browser, from the shown meshes' box in the 3MF's axes (x width, y depth, z height), in mm via `unit` (micron 0.001, millimeter 1, centimeter 10, inch 25.4, foot 304.8, meter 1000); whole mm, one decimal below 10 mm, decimal comma in `de`.
- No accent on the toggles (they use `aria-pressed` with `--fg`, as the mock). Camera moves animate only without `prefers-reduced-motion`.

## Review Focus

### Task 1: The facts reader

**Files:** Create `backend/threemf/{zip,xml,facts,types,index}.ts`, `facts.test.ts`, `xml.test.ts`; `backend/fixtures/plates.3mf` via `make-fixtures.mjs`; modify `backend/client.ts` (export the Facts types and `UNIT_MM`).

**Interfaces (produces):**
- `scanTags(text, onTag)`, `class TagStream { push(chunk); end() }`, `type Tag = { name; attrs; end; selfClosing }` (entities decoded; `<?…?>`, comments, CDATA, doctype skipped; text between tags never kept).
- `type FactsSlot = { slot: number; type: string | null; color: string | null }` (`#rrggbb` lower case).
- `type FactsPart = { key: string; name: string | null; object: string; components: number[] | null; slot: number | null }` (`components`: 0-based indices of the root object's `<component>`s this part covers; null for a mesh object).
- `type Facts = { reader: 1; unit: number; items: string[]; parts: FactsPart[]; slots: FactsSlot[] }` (`items`: the `objectid` of each `<build>` item, in order).
- `readFacts(bytes: Uint8Array): Facts`, throws `FactsError` (`threemf: …`) for a missing root model or too-large-inside; never for odd metadata. `entries(bytes)`, `readEntry(bytes, name, max)`, `scanEntry(bytes, name, max, onText)` in `zip.ts`.

Fixture `plates.3mf` (Bambu-style): root objects 2 (component `object_1.model` id 1, a 20 mm box) and 4 (components `object_2.model` ids 3, 5, 7: 10 mm boxes at x 0, 12, 24), build items 2 at x 0 and 4 at x 300; model_settings: 2 "Halter" extruder 1; 4 "Spule" extruder 1, part 3 extruder 2, part 5 none, part 7 `modifier_part`; project_settings `["#00AE42","#FFFFFFFF"]`, `["PLA","PETG"]`.
