# preview v0.2, step 3: print figures and the slicer, implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** every version shows what it takes to print it (time, weight, grams per filament, for the whole model), read from the file when
Bambu Studio sliced it, otherwise asked of the slicing service by an in-process worker.

**Architecture:** `backend/threemf/facts.ts` adds `figures` (from `Metadata/slice_info.config`, summed over plates) to the facts
(READER 2, so stored versions are read again at start). A new `slice_jobs` table holds the slicer's work per version (pending, done with
its figures, failed with a reason), apart from the facts, so a re-read never loses the slicer's answer. `backend/slicer.ts` is the
service's client and the worker: started from `instrumentation.ts`, it adds a job for every version without figures, then works the due
jobs one at a time. `backend/figures.ts` answers a version's figures and slicing state for every surface.

**Tech Stack:** Next.js 16, next-app-kit, SQLite (kysely + better-sqlite3), vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-27-preview-v0.2-design.md` (goal 6, "Slicing for files without figures").

## Global Constraints

- Settings: `PREVIEW_SLICER_URL` (optional; unset: no figures for files without them, nothing else changes), `PREVIEW_SLICER_TOKEN`
  (optional, sent as `Authorization: Bearer`), `PREVIEW_SLICER_MATERIAL` (`PLA` or `PETG`, default `PLA`), in `.env.example` and
  `docs/configuration.md` too.
- Service: `POST /estimate`, multipart `file` (≤ 50 MB) and `material`; answers `{ok, grams, minutes, filaments[{slot,type,color,grams}]}`.
- Retries: 429, 503, 504 and a network failure are tried again with backoff, at most 5 attempts over about an hour; 400, 413, 422 are
  final. A file over 50 MB fails without a call.
- The customer page shows "wird berechnet" while pending and nothing when failed; the web app shows the failure and "Neu berechnen"
  (MCP `reslice_version`, REST `POST /versions/{id}/slice`).
- No literal text in JSX; logs carry no token, link token, file name or email.
- Appended migrations only; MCP and REST mirror each other; `npm run generate` writes `openapi.json`.

## Review Focus

- A Bambu project sliced only on some plates: the sum of the sliced plates is shown (a ruling; the file says nothing of the rest).
- A restart while a job is in flight: the job is still pending and is worked again.
- A re-read of facts (`reread_facts`) on a version the slicer answered: the slicer's figures stay.
- The slicer unset after jobs were made: nothing is shown as pending; the jobs wait.
- A service that answers 200 with a body that isn't an estimate: failed, with a reason, not a crash.
